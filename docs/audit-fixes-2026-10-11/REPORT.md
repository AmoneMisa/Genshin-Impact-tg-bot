# Исправления по аудиту от 11 октября 2026

В рабочую копию внесены исправления для всех 14 находок [исходного аудита](../audit-2026-10-11/REPORT.md). Разделение физической и магической боевой механики и двухколоночные характеристики выполнены ранее; их проверки входят в общий прогон. Изменения не опубликованы.

## Что исправлено

| № | Находка | Результат |
|---|---|---|
| 1 | Создание валюты при межчатовых переводах | Запись Character всегда проверяет ревизию. Изменённая устаревшая копия вызывает конфликт 409, включая одинаковые суммы списаний. Chat, его участники и гости сохраняются в одной MongoDB transaction: конфликт откатывает также уже записанные зачисления. Транзакция вызывающего кода переиспользуется. |
| 2 | Запись игровой модели во время авторизации | Авторизация получает несохраняемую копию Chat/User. Создание и нормализация с сохранением выполняются под общим reentrant chat lock. Presence bootstrap тоже сохраняется внутри него. Optimistic concurrency защищает версию Chat между процессами. |
| 3 | Ошибки разбора Host вне обработчика запроса | URL разбирается с фиксированным origin. Общая граница обрабатывает ошибки HTTP callback, неправильный URL получает 400. Проверены настоящий локальный HTTP-сервер, `Host: [`, неправильный URL и доступность после ошибки. |
| 4 | Загрузка всех механик при старте | Экраны открываются через динамический импорт; большой каталог предметов заменён маленьким UI-каталогом в начальном графе. Сервер отдаёт основную CSS-связку, остальные стили загружаются перед первым игровым окном. При пустой очереди уведомлений отложенные стили не запрашиваются. |
| 5 | Фоновый GPU и двойной blur | На устройстве с ≤4 ядрами, ≤2 ГБ памяти, Save-Data или reduced motion используется статичный фон. На остальных фон приостанавливается при скрытии документа и под модальным окном. Вложенный backdrop-filter панелей удалён. |
| 6 | Перекрывающийся polling и поздние ответы | Обновления босса, охоты и атласа запускаются последовательно, с backoff и паузой при скрытии. Действие/закрытие отменяет старый запрос и делает его ответ недействительным. Общий API timeout — 20 секунд. POST автоматически не повторяется. |
| 7 | Вложенная рамка рыбалки | Удалены декоративная рамка, её padding и угловые украшения. Сцена занимает доступные 278 px вместо 244 px на экране 320 px. |
| 8 | Перенос числа в кошельке | Валюты занимают два столбца; действия вынесены отдельно. Числа не переносятся, большие значения сокращаются, полное значение остаётся в title. Проверены 33 000, 1 234 567 и Number.MAX_SAFE_INTEGER. |
| 9 | Маленькие мобильные кнопки | Основным кнопкам, вкладкам и кнопкам закрытия задана зона 44 px. Дополнительно исправлены кнопки сундука, аркады, магазина, инвентаря и хранилища. В 22 проверенных состояниях нет видимых кнопок меньше 40 px. |
| 10 | Разные отступы и поверхности | Добавлены spacing tokens 4/8/12/16/24 px. Окно персонажа использует общую золотую палитру, радиус 14 px и поверхность окна. Дублирующие inset-рамки и коробки секций удалены. |
| 11 | Фокус уходит под окно | Общий lifecycle задаёт доступное имя, удерживает Tab/Shift+Tab, делает нижние слои inert и возвращает фокус. Проверены вложенные окна и закрытие сундука через Escape. |
| 12 | Неработающие команды в справке | Удалён каталог старых команд; справка описывает актуальные пути внутри Mini App и запуск через /play или /start. |
| 13 | Лишняя коробка обратной связи | Вводный текст больше не оформлен отдельной рамкой с вложенными отступами. |
| 14 | Синхронные операции в HTTP callback и рост лога | CSS-связки готовятся до listen; stat/read/compression выполняются асинхронно, gzip кэшируется. Ошибка чтения файла закрывает поток ответа. Запись глобальных ошибок асинхронная, лог ротируется при 5 МБ в один резервный файл. |

## Проверки и размеры

Полный `node --test`: **948 тестов, 948 успешных**, 0 ошибок, 0 пропусков; 92,8 секунды. Финальное изменение после прогона — перенос стиля кнопки атласа из отложенного CSS в городской CSS; оно отдельно проверено в браузере.

| Начальная загрузка | До | После |
|---|---:|---:|
| Статический граф JS | 104 модуля | 29 модулей |
| JS исходники | 1 200 897 байт | 118 871 байт |
| JS gzip, сумма файлов | 345 288 байт | 41 861 байт |
| Начальные CSS исходники | 492 086 байт | 100 859 байт |
| Начальный CSS gzip | 98 274 байта | 22 527 байт |

Числа не включают изображения, Telegram SDK и последующие динамические импорты. Первое игровое окно загружает полную CSS-связку для сохранения прежнего порядка каскада; это добавляет повторную передачу основных стилей. Связка загружается один раз и кэшируется. Это оптимизация начальной загрузки, а не уменьшение суммарного CSS всех экранов.

В Chromium проверены 11 экранов × ширины 320/390 px через тот же генератор CSS-связок, который использует сервер. В проверенных состояниях нет ошибок JS и горизонтального переполнения. Дополнительно проверены вложенные модальные окна, крупные балансы и настоящий запуск app.js без загрузки инвентаря/большого каталога/отложенного CSS. GPU probe на обычном профиле: 8 отрисовок до окна, **0 за время паузы**, 6 после закрытия; на слабом профиле — статичный режим.

## Ограничения проверки и запуска

- Экономические тесты используют реальные функции переводов, синхронизации и атомарного сохранения с моделью транзакционного хранилища. Они воспроизводят конфликт двух одновременно загруженных копий и откат зачисления. Интеграционный конкурентный сценарий на настоящей MongoDB здесь не запускался.
- **MongoDB должна поддерживать transactions: replica set либо sharded cluster.** Сохранение намеренно не переключается на небезопасные отдельные записи при недоступности транзакций. Ранее transactions уже использовали обмен, склад и почта; теперь они требуются для каждого Chat.save(). Это необходимо проверить перед публикацией.
- Конфликт возвращает 409; пользователь обновляет состояние и повторяет действие. Автоматического повторения финансовых операций нет. Timeout POST не доказывает отсутствие записи на сервере.
- API в визуальных проверках заменён фикстурами. Не проверялись реальные Telegram-сессии, платежи, production proxy, все игровые состояния и производительность физического слабого телефона.
- Зависимости не менялись; результат npm audit в исходном отчёте — 0 известных уязвимостей на момент его запуска. Это не утверждение об отсутствии любых уязвимостей.
