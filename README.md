# Genshin Impact Game Bot

Телеграм-игра с открытым исходным кодом для групп и личного использования: бот + Telegram Mini App.
Весь игровой интерфейс живёт в Mini App (`/play` в чате или кнопка меню бота); текстовые команды
игры убраны — на любую команду бот отвечает кнопкой «Открыть игру».

Языки интерфейса: русский и узбекский (латиница). Узбекский включается сам, если в Telegram выбран `uz`,
или вручную: Меню → «Til / Язык».

## Что есть в игре

Всё это — экраны Mini App (список — `miniapp/state.js`, раздел `FEATURE_CATALOG`).

**Персонаж**
- Класс, пол, характеристики; дерево классов: 6 базовых классов, у каждого две 2-е и по одной 3-й профессии (20-й и 40-й уровни), квесты профессий;
- Навыки: прокачка (заточка до 10 уровня), пути улучшения, очки навыков (ОП);
- **Баффы класса** (в стиле Lineage II): Might, Shield, Haste, Focus, Death Whisper, Guidance, Wind Walk на 20 минут. Класс изучает набор баффов, уровень баффа (I–III) растёт с уровнем персонажа; жрецы и их профессии могут накладывать баффы на других игроков чата;
- Снаряжение: каталог по грейдам (D–S84), заточка, свитки, кристаллизация, крафт по рецептам, сетовые бонусы, эпическое оружие и украшения с эпических боссов; инвентарь и зелья (HP/MP и баффы);
- Анкеты участников, титулы, шуточный гороскоп, меч («увеличение меча»), ежедневный бонус, сундуки, гача.

**Бои**
- Босс чата: общий рейд, скиллы, свита, фазы, дебаффы; эпические боссы (Королева муравьёв, Кор, Орфен, Закен, Баюм, Фринтеза, Антарас, Валакас) с окнами возрождения;
- Арена (обычная и рейтинговая), ограбление ресурсов, кланы (хранилище, исследования, задания, клановый босс, войны и дружеские дуэли).

**Экономика**
- Золото, кристаллы, железная руда; постройки (дворец, шахта, озеро кристаллов, ковальня, академия, полигон и др.); обменник золота в кристаллы; переводы золота между игроками;
- **Монеты удачи** 🍀 — донатная валюта (см. ниже);
- Магазин за золото, клановый магазин (за ресурсы клана);
- Лут: деньги/опыт/снаряжение, материалы и ОП с боссов, **зелья-баффы** (шанс зависит от ранга босса; на эпических боссах топ-3 получают всегда), сундуки.

**Игры**: «21 очко», «Элементы», кубики, боулинг, дартс, футбол, баскетбол, слоты.

**Аукцион** чата: игроки выставляют снаряжение, зелья и материалы за золото (комиссия 5% с продажи, лот висит 48 ч, потом вещь возвращается; максимум 10 лотов; временные эпики не продаются). Вещь лежит в залоге у лота, поэтому её нельзя потратить дважды.

**Passive-навыки, камни жизни, клановые навыки и RTA** (в духе Lineage II):
- **Пассивные навыки** («Герой» → «Пассивные навыки»): у каждой ветки классов свои 3-5 навыков (мастерство оружия/брони/магии, прилив HP/маны, крит, меткость, лечение…), по 5 уровней за ОП и золото, уровни открываются с 10/25/40/55/70-го уровня персонажа. Бонусы идут через общий расчёт статов (`functions/game/player/extraModifiers.js`); при смене ветки чужие навыки отключаются, но не теряются;
- **Камни жизни** (аугментация C…S84, «Кузница»): камень грейда предмета + золото дают **оружию** или **бижутерии** случайный бонус; новый камень заменяет бонус. Камни четырёх качеств — обычный, средний, высокий, высший (сильнее бонус и дороже золото); у оружия средний/высокий/высший камень с шансом 25/50/80% даёт ещё и **навык**: пассивный (постоянный бонус), «шанс» (срабатывает на ударе) или активный (кнопка на 10 минут, перезарядка час). Бижутерия получает очки **характеристик** (STR/DEX/CON/INT/WIT/MEN) или HP/ману/защиту. Эпические и временные предметы не аугментируются, как в Lineage II (`functions/game/equipment/augment.js`, `lifestoneSkills.js`);
- **Характеристики** (`functions/game/player/baseStats.js`, экран «Пассивные навыки»): у каждой ветки классов стартовые STR/DEX/CON/INT/WIT/MEN из Lineage II, снаряжение добавляет очки. Таблицы L2 (STR 1.036^x и т. д., смягчены и ограничены) дают: STR/INT — атаку (маги и жрецы — INT), DEX — точность, уклонение, скорость боя и крит, CON — HP, WIT — перезарядку навыков, MEN — ману. Без снаряжения игра идёт как раньше;
- **Атрибуты** (`functions/game/equipment/attributes.js`): шесть стихий — огонь, вода, ветер, земля, свет, тьма. Камни/кристаллы/самоцветы атрибута падают с боссов своей стихии; оружие с атрибутом бьёт сильнее (×1,5 по боссу противоположной стихии, ×0,5 по своей), броня и щиты B-грейда и выше дают сопротивление стихии босса и игрока (до −30%). Атрибут можно снять за золото.
- **Клановые навыки** (клан → «Навыки»): 6 навыков по 5 уровней; глава и офицеры учат их за золото и репутацию из хранилища и **яйца** (яйцо виверны / дракона / древнего дракона). Яйца получает хранилище каждого клана, чей игрок бился с эпическим боссом. Бонус получают все участники клана (копия уровней обновляется каждые 10 минут);
- **RTA кланов** (клан → «Войны»): отряд до 5 бойцов — это замороженные копии героев (поэтому бой идёт без игроков и из любого чата; «Обновить бойца» после прокачки). Глава или офицер вызывает клан с рейтингом ±300, бойцы дерутся парами (сильнейший против сильнейшего) движком дуэлей; побеждает отряд с большим числом побед. Рейтинг Эло (старт 1000, K=32), победитель получает 5000 золота и опыт клана, перерыв между боями — час, есть история и топ-10 кланов.

**Социальное**: друзья (взаимные, через заявки), клановые товарищи, карточки игроков, присутствие «В игре», почта с наградами, промокоды, красные точки и пуши в личку Telegram (заявки в друзья/клан, призыв босса и др.).

### Монеты удачи (донатная валюта)

- Покупаются **только за Telegram Stars** (`XTR`) в Mini App: «Обменник» → «Монеты удачи за Звёзды». Наборы и цены — `miniapp/stars.js` (6 наборов от 25★ = 25 🍀 до 1000★ = 1500 🍀, бонус до +50%, бонус первой покупки — до +200 🍀);
- **не воруются**; хранятся в `inventory.luckCoins`. Немного монет можно заработать: каждому, кто бился с эпическим боссом, — от 5 (Королева муравьёв) до 50 (Валакас), а топ-10 арены чата каждую неделю получает 15-10-7-5-5-5-3-3-3-3 почтой;
- тратятся в **«Донат-магазине»** (цены — `template/luckShop.js`, категории-вкладки):
  - **Временные эпики** — аренда на 7 дней эпического оружия и украшений, доступных классу игрока (нужен уровень грейда); повторная покупка продлевает срок, по окончании предмет снимается, продать/разобрать/выставить на аукцион его нельзя;
  - **Свитки** заточки в стиле Lineage II для грейдов A, S, S80, S84: благословенные (при неудаче — на безопасный уровень) и нерушимые (при неудаче предмет и уровень остаются) — отдельно для оружия и для брони;
  - **Эликсиры** жизни/духа/CP грейдов A и S (по 5 шт., нужен 61/76 уровень);
  - **Материалы ковки** — наборы всех четырёх материалов грейда + руда;
  - **Баффы** — зелья-баффы; **Кристаллы** (7 дней защищены от ограбления); **Попытки** (сундуки, бонус, арена, ограбление);
- каждая покупка записывается в коллекцию `star_purchases`: платёж засчитывается один раз (по id платежа Telegram), недоначисленные покупки дозачисляются при старте. Покупки, сделанные до появления монет, остаются кристальными (`currency: crystals`) и так же начисляются/возвращаются;
- иконка монеты — оригинальная (золотая монета с клевером, не из Lineage II), рисуется скриптом `scripts/world/make-luck-coin.py` в `webapp/art/world/v1/currency/`;
- команды: `/paysupport` (поддержка по оплате — требование Telegram) и `/refund_stars ID` (только владелец: вернуть Stars и списать монеты).

## Админка (только владелец бота, `ADMIN_ID`)

Карточка «Админка» в Меню (видна только владельцу, права проверяются на сервере):
- **Промокоды**: награды (золото, кристаллы, монеты удачи, руда, попытки бонуса), даты начала/окончания, лимит использований, один раз на игрока; награда приходит в **почту** (хранится 180 дней);
- **Объявления** — окна «Привет» при открытии Mini App («не показывать сегодня»);
- **Инструменты**: выдача ресурсов/монет/опыта/попыток игроку, сбросы таймеров и игр, убить босса, пересчёты, рассылка новостей, лог бота.

Остались текстовыми командами владельца (в `onTextsAdmin/`): `/get_file`, `/send_file`, `/get_chat_data`, `/update_users`, `/clear_all_sessions`.

## Запуск локально

Нужны Node.js 24 и MongoDB.

```bash
npm ci
cp .env.example .env     # BOT_TOKEN, ADMIN_ID, MONGO_URL, MINI_APP_URL, ...
npm run run              # бот + сервер Mini App (miniapp-entry.js)
npm test                 # тесты (node --test)
```

Токен и id владельца можно положить в `config.js` (он в `.gitignore`), он приоритетнее `.env`:

```js
export let token = 'токен бота от @BotFather';
export let myId = 123456789; // ваш Telegram user id, числом
export let giantBombApiKey = '';
```

Переменные окружения (`.env.example`): `BOT_TOKEN`, `ADMIN_ID`, `MONGO_URL`, `MINI_APP_ENABLED`, `MINI_APP_PORT`, `MINI_APP_HOST`,
`MINI_APP_URL` (публичный HTTPS), `MINI_APP_SHORT_NAME` (имя Mini App в BotFather — нужно для кнопки «Открыть игру» в группах),
`FREE_LLM_*` (необязательный прокси для текстов гороскопа; без него используются запасные фразы).

В BotFather настрой Main Mini App бота на `MINI_APP_URL`.

## Устройство проекта

| Папка | Что внутри |
|---|---|
| `miniapp/` | HTTP-сервер Mini App и серверная логика экранов (`server.js` — API, `state.js` — DTO игрока, `stars.js`, `luck.js`, `buffs.js`, `promo.js`, `adminTools.js`, …) |
| `webapp/` | клиент Mini App: экраны, WebGL/3D, стили; `i18n/` — перевод |
| `functions/` | игровая логика, общая для сервера и планировщиков (бой, снаряжение, кланы, расписания в `shedullers/`) |
| `template/`, `dictionaries/` | игровые данные: классы, навыки, боссы, предметы, магазины |
| `db/` | модели Mongoose и загрузка шаблонов |
| `onTextsAdmin/` | оставшиеся текстовые команды владельца |
| `scripts/` | сборка арта, баланс, перевод (`scripts/i18n/`), хэши шаблонов |
| `test/` | тесты (`npm test`) |
| `art-source/` | исходные картинки (PNG-мастера); готовый веб-арт — `webapp/art/` (всё в WebP), скриншоты проверок — `docs/*.webp` (скрипты `scripts/*/browser-check.js` сразу пишут WebP через `scripts/lib/screenshot-webp.mjs`) |

Принципы: награды, ГСЧ, таймеры и валюта считаются только на сервере; initData Telegram проверяется на каждый запрос;
каждый чат читается и сохраняется под своим локом (`functions/general/chatLock.js`), чтобы Mini App и планировщики
не затирали друг друга (иначе `VersionError`).

**Шаблоны игры** (статы и навыки классов, снаряжение, постройки, боссы, зелья, магазин, уровни и т.д.) хранятся в Mongo,
коллекция `game_templates`. Файлы `template/*.js` — начальные данные: при первом запуске они записываются в Mongo, дальше
**побеждает Mongo**. Чтобы изменить баланс через код: правь файл в `template/`, подними `version` шаблона в `db/templates.js`
и обнови хэши: `node scripts/templates/hash.mjs > template/seedHashes.js` (тест `test/templates.test.js` напомнит).

### Переводы

Игра пишется по-русски; слой `webapp/i18n/` переводит готовый экран (тексты, подсказки, диалоги, текст на canvas), поэтому
экраны про языки не знают. Сообщения бота в личку (пуши, кнопка запуска, рассылка) переводятся на сервере.
Новая русская строка → `node scripts/i18n/missing.mjs` покажет, чего нет в `webapp/i18n/uz.js`, перевод добавляется в
`webapp/i18n/uz-extra.js` (`'Русская фраза': "O'zbekcha"`, части переменного текста — `{0}`, `{1}`);
тест `test/i18n.test.js` падает, если фраза осталась без перевода. Узбекский перевод сделан без носителя языка — нужна вычитка.

## Тесты и CI

- `npm test` — около 600 тестов (логика, балансировка классов, платежи Stars, i18n, расписания под локами);
- GitHub Actions (`.github/workflows/miniapp-ci.yml`) при каждом пуше в `master`: тесты → сборка образа → публикация в GHCR.
  Тестам нужен `config.js`, а он секретный, поэтому CI создаёт фиктивный;
- деплой — на сервере (`docker compose pull && docker compose up -d` или `./docker/update.sh`, см. ниже).

## Запуск в Docker

В контейнере работают бот и сервер Mini App (`node miniapp-entry.js`, Node.js 24 LTS), рядом — MongoDB 8.0 (LTS).
Токен в образ не попадает: `config.js` и `.env` исключены через `.dockerignore`,
а `docker/entrypoint.sh` создаёт `config.js` из переменных окружения при старте.

**1. Настройки.** Скопируй пример и заполни:

```bash
cp .env.example .env
```

- `BOT_TOKEN` — токен бота от @BotFather;
- `ADMIN_ID` — твой Telegram user id (админ-команды);
- `MINI_APP_URL` — публичный HTTPS-адрес Mini App;
- `MINI_APP_PORT` — (необязательно) порт Mini App, по умолчанию `8080`; если он занят на сервере, задай другой (compose пробрасывает тот же порт);
- `DOCKER_MONGO_URL` — (необязательно) внешняя MongoDB; по умолчанию — встроенная `mongo`.

> Внутри контейнера `localhost` — это сам контейнер. Для сервисов на хосте
> (например, FreeLLMAPI) используй `http://host.docker.internal:3001/v1`.

**2. Запуск.** Образ собирается на GitHub Actions при каждом пуше в `master`
(сначала тесты, затем сборка и проверка образа) и публикуется в GHCR —
на сервере ничего собирать не нужно:

```bash
docker compose pull
docker compose up -d
docker compose logs -f bot
```

Обновление до свежей сборки с очисткой старых образов:

```bash
./docker/update.sh
```

Скрипт скачивает новый образ, пересоздаёт изменившиеся контейнеры и удаляет мусор:
старые версии образов бота и Mongo (у которых тег переехал на новую версию) и
неиспользуемые анонимные тома. **База данных (`mongo-data`) и данные бота (`bot-state`)
никогда не удаляются**: это именованные тома с меткой `com.genshin-bot.keep=true`,
которую очистка пропускает, а если Mongo не запущена — очистка не выполняется вовсе.
Чистка томов включается только на Docker 23+, где `volume prune` не трогает именованные тома.

Автообновление каждую ночь (cron на сервере):

```bash
0 5 * * * /opt/bot/docker/update.sh >> /var/log/bot-update.log 2>&1
```

В GHCR хранятся 10 последних сборок (для отката: `BOT_IMAGE=ghcr.io/amonemisa/genshin-impact-tg-bot:sha-<коммит>`),
более старые версии CI удаляет сам.

> Пакет в GHCR по умолчанию приватный. Либо сделай его публичным
> (GitHub → Packages → genshin-impact-tg-bot → Package settings → Change visibility),
> либо один раз войди на сервере токеном с правом `read:packages`:
> `docker login ghcr.io -u <github-логин>`.

Собрать образ локально из текущего кода:

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

**Cloudflare Tunnel** для публичного адреса Mini App (токен туннеля — в `TUNNEL_TOKEN`,
в панели Cloudflare направь hostname на `http://bot:8080`):

```bash
docker compose --profile tunnel up -d
```

**Внешняя MongoDB** (например, Atlas) — задай `DOCKER_MONGO_URL` и запусти только бота:

```bash
docker compose up -d --no-deps bot
```

**Данные.** Лог ошибок хранится в томе `bot-state`, база — в томе `mongo-data`; оба переживают пересборку и перезапуск.
